🛠️ Troubleshooting Workflows

−

Explain a Failing Terminal Command

  1. Run the command in the VS Code integrated terminal.
  2. Open Copilot Chat.
  3. Type @terminal /explain.
  4. Review the explanation, including likely failure causes and safer alternatives.

Fix an Error from the Problems Panel

/fix #problems

Understand a Stack Trace

  1. Select the stack trace in the terminal.
  2. Ask Copilot to connect the trace back to likely responsible files.
@workspace explain #terminalSelection and point me to the file most likely responsible

Debug with the Debugger

Set a breakpoint, pause execution, then use inline chat to ask why a variable has an unexpected value.

why is variable X null here?

Turn Changes into a Commit Message

Write a conventional commit message for #changes

Understand an Unfamiliar Codebase Quickly

@workspace give me a tour of this repo — entry points, main modules, and how data flows @workspace where is <feature> implemented?

🧠 Building Faster: Prompt Patterns That Work

−

Role + Goal + Constraints

You are a senior Python engineer. Refactor #selection to use dataclasses. Keep the public API unchanged and add type hints. Do not add new dependencies.

Ask for a Plan Before Code

@workspace outline the steps to add JWT auth to this API. Don't write code yet — just the plan and files that will change.Then follow up with: Great — implement step 1.

Generate Tests First

/tests for #file:src/services/pipeline.py covering happy path, empty input, and network failure.

Explain Then Modify

/explain #selectionNow rewrite it to stream results instead of buffering.

Use #codebase for Cross-File Reasoning

#codebase where do we validate customer IDs, and is the logic consistent everywhere?

✅ Discovery Cheat Sheet

−
  • @terminal /explain after any command you don't fully understand.
  • /fix #problems on the next red squiggle you see.
  • Ask @workspace for a tour of a repo you recently joined.
  • Ask Copilot to write your next commit message from #changes.
  • Install gh copilot and alias ghcs / ghce.
  • Try Agent mode on a small task, such as adding a README badge.
  • Use /tests on a function that has no tests.
  • Ask @vscode how to configure something in the editor instead of searching the web.

🤝 Tips, Gotchas, and Etiquette

−
1
Context is king. The more relevant files, selections, and codebase context you add, the better the answer.
2
Iterate — don't restart. Follow-up prompts are cheaper and better than starting fresh.
3
Verify before you run. Especially with command suggestions — read the command or explain it first.
4
Don't paste secrets. Redact tokens, connection strings, and PII before prompting.
5
Use /clear. Reset old context when switching topics.
6
Keyboard shortcuts pay off. Memorize inline chat and chat view shortcuts first.

⌨️ CLI Overview

−

gh copilot and Copilot CLI bring Copilot to the terminal for scripting, ops work, shell help, Git help, and quick explanations away from VS Code.

Two Core gh copilot Commands

CommandPurpose
gh copilot suggestAsk Copilot to suggest a shell, Git, or GitHub CLI command.
gh copilot explainAsk Copilot to explain a command before you run or reuse it.
Examples: gh copilot suggest "find all files larger than 100MB modified in the last 7 days" gh copilot suggest -t git "undo my last commit but keep the changes staged" gh copilot explain "git rebase -i --autosquash HEAD~5"
Aliases: Use gh copilot alias -- bash >> ~/.bashrc or your shell equivalent to add ghcs and ghce.

  • ! = "Hey terminal, run this command"
  • & = "Hey GitHub, take this task and run with it"

⚡ CLI Power Tips

−
1
Batch context loading: Reference multiple files at once with @src/models/User.cs @src/models/Task.cs Compare these models.
2
Context management: Use /compact when context fills up.
3
Tab completion: Type @ then use Tab to autocomplete file paths.
4
Escape hatch: Use ! for quick shell commands.
5
Model switching: Use /model to balance speed and capability.
